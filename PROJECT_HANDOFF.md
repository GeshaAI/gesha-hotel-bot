## Архитектура и файлы

- `app.py`: сервер стандартной библиотеки Python; SQLite, tenant-bound users/sessions/guest_keys/requests, API ролей, настройки, выдача гостевых ссылок. Нет стандартного пароля и fallback на ADMIN_KEY.
- `docs/index.html`, `docs/staff.html`: раздельные страницы; GitHub Pages — явное локальное демо. Сервер отдаёт те же файлы, добавив `data-runtime="server"`. Ошибка API никогда не переключает серверный режим в демо.
- `index.html`: точная копия гостевой страницы для совместимости; сервер читает docs. При изменении гостевого HTML синхронизировать копию. Не использовать корень репозитория как production webroot: там серверный код.
- `docs/ui.js`: общий UI, localStorage-адаптер демо / HTTP-адаптер сервера, настройки, задачи, темы, язык.
- `docs/engine.js` + `docs/rules.json`: правила и уточнение комнаты. Python читает те же правила, сохраняя порядок guards → issues → faq. Guards дают уточнение вместо автоматической заявки.
- `docs/i18n.json`, `docs/style.css`: четыре языка и адаптивный дизайн.
- `telegram_adapter.py`: необязательный long polling, привязка приватного чата к guest key, общая функция chat.
- `ai_provider.py`: необязательный серверный классификатор намерения; свободные ответы модели запрещены; отключён по умолчанию.
- `tests/test_app.py`, `tests/test_ai.py`: сервер/изоляция/адаптеры.
- `tests/engine.test.cjs`: распознавание и переводы.
- `tests/browser.cjs`: браузерный demo/server E2E, 360/390/412/800 px, временные серверы/БД.
- `.github/workflows/checks.yml`: бесплатный публичный runner; никаких артефактов, лимит 10 минут.

## Модель доступа

Guest — случайный токен с TTL 7 дней, tenant и необязательная комната привязаны сервером. Guest не читает заявки персонала. Staff — только назначенные ему задачи своего tenant; меняет следующий статус. Manager — заявки, назначения, настройки, гостевые ссылки своего tenant. Owner — дополнительно создаёт пользователей. Все записи и назначения фильтруются сервером; скрытые UI-разделы не являются защитой.

Пароли scrypt, сессии 8 часов, token hashes в SQLite, HttpOnly + SameSite=Strict + Secure по умолчанию. JSON + обязательный custom header без CORS, лимиты login/chat. База не раздаётся HTTP и исключена из Git. SQLite SQL параметризован.

## Проверки и ограничения

См. `TEST_REPORT.md`: локально прошли 17 Python-тестов, 6 JS-групп и Chromium E2E на 8 сочетаниях demo/server × 360/390/412/800 px. Воспроизведено стирание комнаты задержанным серверным config на старой версии; обычный demo-сценарий 8 работал и раньше. Telegram и ИИ по-прежнему не проверялись с реальными внешними сервисами.

**Это v0.4 pilot, не готовый коммерческий SaaS.**
- Внешний backend ещё не развёрнут; Pages не исполняет Python и не имеет общей базы.
- Нет password reset, отключения сотрудника из UI, принудительного отзыва guest links из UI, MFA, аудита изменений, резервных копий/retention-процессов.
- Нет идемпотентности повторной HTTP-заявки после потери ответа; повторная отправка может создать дубликат.
- Telegram offset сохраняется до обработки: сбой может потерять сообщение. Нужен durable inbox/outbox. Глобальный старый STAFF_CHAT_ID отключён, чтобы не смешивать гостиницы; tenant-scoped уведомления пока отсутствуют.
- Нет WhatsApp, QR-image generator, свободно создаваемых пользовательских FAQ, automatic translation, push-обновлений статуса гостю, подтверждения принадлежности гостя реальному бронированию.
- Список языков обслуживания сохраняется как настройка; интерфейс оставляет выбор всех четырёх языков.
- Простые правила не понимают любую естественную речь. ИИ требует явной серверной конфигурации; никто не подключал платную модель.
- Python HTTP server требует HTTPS proxy с таймаутами/лимитами перед внешним пилотом. Полного security/load/privacy-аудита нет.

## Изменения v0.4.1 и правила продолжения

- Номер комнаты снимком перед отправкой; серверный config не затирает пользовательский ввод пустым значением. `boundRoom` применяется на клиенте, но защита остаётся в серверном `key['room'] or ...`.
- Нормализация комнаты NFKC, пробелы и однозначный номер 8. Визуальная подсказка выбранной комнаты.
- Полный ID сохранён в API/SQLite/localStorage; последние 8 букв/цифр только для показа. **Не использовать короткую метку как идентификатор операции**. Старые ID не переписываются. Новые demo ID — полный UUID.
- Подтверждения содержат комнату и категорию. Demo явно сообщает, что персоналу ничего не отправлено.
- Новая группа `guards` в rules.json для неоднозначных вопросов, позднего выезда и не-заявок. Общий fixture `tests/phrases.json` проверяется Python и Node. Не менять широкие regex без проверки отрицательных/информационных примеров.
- Настройки сгруппированы; статус заполнения и 9 основных полей относятся к выбранному языку. Часы по умолчанию не задаются. Сохраняется прежняя схема settings и ключ `gesha-hotel-demo-v04`.
- Прокрутка чата после render через requestAnimationFrame; форма ввода в обычном потоке, кнопки ≥44 px. Динамическая высота чата и одна горизонтальная строка быстрых вопросов на смартфоне.
- Старые данные остаются. Не запускать очистку localStorage или SQLite при обновлении версии.
- Дальше: физический Android smoke-test, затем idempotency и безопасные уведомления. Публичный backend не разворачивать без отдельного согласования; платные услуги не включать.
