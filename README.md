# GESHA HOTEL BOT · v0.4.1

Продолжение v0.4: помощник небольшой гостиницы, гостевой веб-чат, заявки и панель персонала на RU / DE / EN / UK.

**[Открыть публичное демо](https://geshaai.github.io/gesha-hotel-bot/?v=0.4.1)** · **[Демо-панель](https://geshaai.github.io/gesha-hotel-bot/staff.html?v=0.4.1)**

## Два режима — разные возможности

| | GitHub Pages: демо | Python-сервер: пилот |
|---|---|---|
| Гостевой чат, настройки, темы | Да | Да |
| Заявки | Только этот браузер | Общая SQLite-база |
| Вход и роли | Нет, явная пометка «демо» | Пароли, серверные сессии, Staff / Manager / Owner |
| Изоляция гостиниц | Нет реальных гостиниц | Tenant из сессии / гостевого токена; проверки API |
| Telegram | Нет | Необязательный адаптер; требуется токен |
| ИИ | Нет | Необязательный серверный маршрутизатор; отключён |

**Публичный сайт не является развёрнутым SaaS.** Не вводите реальные данные гостей в демо. Сервер не размещён на внешнем хостинге. Платные сервисы не подключены.

## Исправления v0.4.1

- Верхнее поле комнаты считывается перед отправкой. Поздний ответ `/api/config` больше не стирает введённое значение; серверно привязанная комната по-прежнему имеет приоритет.
- Явная подсказка, какая комната будет использована; нормализация пробелов и цифр с мобильной клавиатуры. Для отсутствующего номера сохраняется уточнение.
- Компактные сообщения, одна прокручиваемая строка быстрых вопросов на смартфоне, элементы отправки не перекрывают чат. Проверки 360/390/412/800 px и уменьшенной высоты окна.
- Короткий номер заявки — последние 8 букв/цифр ID. Полный ID не меняется: хранится в данных, API и раскрываемой карточке персонала. Короткая метка не является уникальным ключом для операций.
- Настройки сгруппированы: питание, проживание/услуги, сведения гостиницы. Отмечены заполненные/пустые поля, показан счётчик 9 основных полей для текущего языка и фильтр незаполненных.
- Бот перечитывает сохранённые настройки демо при вопросе: изменения другой открытой вкладки используются без перезагрузки гостевого чата.
- Неоднозначное «Во сколько кормят?» вызывает уточнение приёма пищи. Поздний выезд требует согласования, без обещаний. Отдельное слово «полотенца» или вопрос об отоплении не создаёт автоматическую заявку.
- Существующие данные v0.4 сохранены: прежний localStorage key, схема SQLite и полные ID заявок. Миграция/очистка данных не требуется.

## Возможности

- Единый UI для демо и сервера; отдельные гостевая страница и служебная панель.
- Приоритет неисправностей перед FAQ: «не работает интернет» создаёт обращение, а не показывает Wi-Fi.
- Обед, ужин, выезд, естественные ответы «комната 12», «Zimmer 12»; отмена уточнения, общий запрос помощи требует подробностей.
- Переводы интерфейса и ответов, автоматическое определение языка по ограниченным признакам; ручной выбор доступен всегда.
- Название, HTTPS-логотип, адрес, контакты, питание, заселение/выезд, Wi-Fi, парковка, услуги, магазин, такси и информация для гостей. Тексты заполняются отдельно для каждого языка. Нет перевода — нет выдуманного ответа.
- Уникальный ID заявки, комната, описание, категория, приоритет, время UTC, статус, сотрудник.
- Статусы: новая → принята → в работе → выполнена. Назначение и приоритет меняет Manager/Owner; Staff видит и обрабатывает свои заявки.
- Светлая/тёмная тема; адаптивная сетка; versioned assets; серверный `Cache-Control: no-store`; service worker отсутствует.
- Старые записи демо v0.2/v0.3 импортируются без удаления исходных ключей.

## Запуск серверного пилота

Python 3.12+, дополнительных Python-пакетов нет.

```bash
python app.py init-hotel haidmuehle "Hotel name" owner
# Введите уникальный пароль длиной не менее 12 символов в скрытом приглашении.
# Только для локального HTTP-теста:
COOKIE_SECURE=0 python app.py
```

Откройте `http://localhost:8080/staff`. Войдите с кодом `haidmuehle`, именем `owner` и заданным паролем.

1. Заполните настройки; при смене языка заполните переводы и нажмите «Сохранить».
2. Владелец создаёт сотрудников и управляющих внизу панели.
3. Создайте гостевую ссылку. Она действует 7 дней; указанная комната привязана на сервере. Пустая комната вызывает уточнение в чате.
4. Откройте ссылку на гостевом устройстве. Для другого устройства нужен доступный ему HTTPS-адрес сервера.
5. Управляющий назначает заявку; сотрудник меняет её статус.

Для второй гостиницы повторите `init-hotel` с другим кодом. Существующая гостиница не перезаписывается.

Переменные: `HOTEL_DB` (путь к SQLite), `HOST` (по умолчанию 127.0.0.1), `PORT` (8080), `COOKIE_SECURE` (по умолчанию 1).

**Перед внешним пилотом:** HTTPS reverse proxy с лимитами соединений и размера тела, `COOKIE_SECURE=1`, отдельный системный пользователь, закрытый файл БД, резервное копирование и согласованная политика хранения. Встроенный Python HTTP-сервер — пилотный транспорт, не промышленный gateway. Никогда не публикуйте SQLite, `.env` или токены в GitHub. База и ключи не раздаются статическим HTTP-маршрутом.

Старые таблицы `tickets` и `faq` Python v0.1 сохраняются, но автоматически не приписываются гостинице. Для импорта нужен явный выбор владельца этих данных. Старый `ADMIN_KEY` больше не даёт доступ.

## Интеграции

### QR-веб-чат

Сервер выдаёт ссылку `/#access=<случайный токен>` для использования в QR-коде. Токен хранится хешированным в БД, не передаётся в URL API и не записывается в localStorage. Это bearer-доступ к гостевым действиям: не публикуйте реальные гостевые ссылки. Генерация картинки QR в v0.4 не добавлена.

### Telegram

Установите `TELEGRAM_BOT_TOKEN` только в окружении сервера; запускайте один процесс polling на бота. Гость связывает приватный чат командой `/start <access token из гостевой ссылки>`; затем используются те же tenant, комната, FAQ и заявки. `/cancel` отменяет уточнение комнаты. Истечение гостевой ссылки прекращает доступ Telegram.

Реальная связь с Telegram в этой версии не проверена без предоставленного токена. Адаптер протестирован локально без сети. В v0.4 polling сохраняет offset **до** обработки: сбой между сохранением и ответом может потерять сообщение; транзакционный inbox/outbox — следующая задача. Уведомления персоналу и обновления статуса гостю ещё не подключены. Старый глобальный `STAFF_CHAT_ID` намеренно не используется: он мог бы смешать данные разных гостиниц.

### ИИ через сервер

`ai_provider.py` — необязательный intent router для OpenAI-совместимого `chat/completions` API. По умолчанию никаких внешних запросов нет. Настройка только после выбора провайдера и разрешения расходов/передачи данных:

- `ENABLE_LLM_ROUTER=1`
- `LLM_ENDPOINT` — полный URL `.../v1/chat/completions`
- `LLM_MODEL`
- `LLM_API_KEY` — только серверная переменная (если провайдер требует ключ)

Сначала работают локальные правила. Для неизвестной фразы модель возвращает только допустимую категорию; её свободный текст гостю не показывается. Часы, цены и услуги берутся из настроек конкретной гостиницы. При ошибке/таймауте/невалидном JSON — уточняющий вопрос. Перед активацией учитывайте, что провайдер получит текст сообщения гостя. Реальная модель не подключена; контракт проверен заглушкой.

WhatsApp через официальный API — следующий этап; адаптера и каких-либо неофициальных обходов нет.
